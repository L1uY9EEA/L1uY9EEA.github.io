扫码器读取

发表于2026-06-11|更新于2026-06-12|PLC 学习
|浏览量:



这段程序可以理解成：PLC 同时接收 4 个扫码器的数据，当收到指令 #nn = 121 时，从 4 个扫码器里找一个有内容的码，前面加上 DL，保存到 #aa.sm。
整体流程是：
4 个扫码器一直在监听
↓
扫码器扫到条码后，数据进入 #s1 / #s2 / #s3 / #s4
↓
当 #nn = 121 时，PLC 开始取码
↓
优先取 #s1，其次 #s2，再 #s3，再 #s4
↓
取到后前面加 DL
↓
保存到 #aa.sm
↓
清空已经取走的扫码数据

  1. 四个接收功能块
    “TRCV_C_DB_2”(EN_R:=1,
    CONT:=1,
    ADHOC:=1,
    STATUS=>#www,
    CONNECT:=#s11,
    DATA:=#s1);

这个是第 1 个扫码器接收。
参数 含义
EN_R:=1 允许接收数据
CONT:=1 连续接收
ADHOC:=1 不固定长度，收到一段数据就接收
STATUS=>#www 接收状态码，用来判断通讯有没有错误
CONNECT:=#s11 第 1 个扫码器的连接参数
DATA:=#s1 接收到的扫码内容放到 #s1

后面三个一样：
“TRCV_C_DB_3” DATA:=#s2 CONNECT:=#s22
“TRCV_C_DB” DATA:=#s3 CONNECT:=#s33
“TRCV_C_DB_1” DATA:=#s4 CONNECT:=#s34
可以这样记：
扫码器 连接参数 接收数据
1 号扫码器 #s11 #s1
2 号扫码器 #s22 #s2
3 号扫码器 #s33 #s3
4 号扫码器 #s34 #s4

  1. #nn = 121 是取码指令

IF #nn = 121 THEN
这句意思是：
当触摸屏、上位流程、或者其他程序给了 121 指令时，
PLC 开始检查有没有扫码数据。
也就是说，扫码器平时一直收码，但真正把码拿去用，是在 #nn = 121 的时候。
3. 判断哪个扫码器有数据
IF #s1 <> ‘’ THEN
意思是：
如果 #s1 不是空字符串，说明 1 号扫码器扫到了码。
然后：
#aa.sm := CONCAT(IN1 := ‘DL’, IN2 := #s1);
#s1 := ‘’;
意思是：
把 ‘DL’ 和 #s1 拼接起来
保存到 #aa.sm
然后把 #s1 清空，避免下次重复使用
例如：
#s1 = ‘ABC123’
执行后：
#aa.sm = ‘DLABC123’
#s1 = ‘’
4. 为什么用 ELSIF
IF #s1 <> ‘’ THEN
…
ELSIF #s2 <>’’ THEN
…
ELSIF #s3<>’’ THEN
…
ELSIF #s4<>’’ THEN
…
END_IF;
ELSIF 的意思是：只取一个扫码器的数据。
优先级是：
#s1 优先
#s2 第二
#s3 第三
#s4 第四
如果 1 号和 2 号扫码器同时有数据，程序只会取 1 号扫码器的数据，2 号会留到下一次 #nn = 121 再取。
5. #nn := 0 的含义
#nn := 0;
意思是：
取码指令执行完后，把指令清零。
这样程序不会一直重复执行 121。
不过这里有一个小注意：
你现在的写法是，只要 #nn = 121，不管有没有扫码数据，最后都会把 #nn 清零。
也就是说：
如果 4 个扫码器都还没扫到码，
#nn = 121 也会被清掉，
这次取码就结束了。
如果你希望“没扫到码就继续等”，那逻辑要稍微改一下。
6. 这段程序代表的现场动作
现场可以这样理解：
扫码器 1、2、3、4 一直等待产品经过
产品经过时，扫码器扫到条码
PLC 把条码暂存在 #s1/#s2/#s3/#s4
流程需要用码时，给 #nn = 121
PLC 从 4 个暂存区里取一个码
前面加 DL
存到 #aa.sm
然后清空这个扫码器的缓存
变量说明
变量 代表什么
#s1 1 号扫码器收到的条码
#s2 2 号扫码器收到的条码
#s3 3 号扫码器收到的条码
#s4 4 号扫码器收到的条码
#s11 1 号扫码器通讯连接参数
#s22 2 号扫码器通讯连接参数
#s33 3 号扫码器通讯连接参数
#s34 4 号扫码器通讯连接参数
#aa.sm 最终保存的扫码结果
#nn 外部指令号，121 表示取扫码数据
#www 第 1 个接收块的状态码
#qqq 第 3 个接收块的状态码

一句话总结：
TRCV_C 负责一直收扫码器发来的字符串，#nn = 121 负责触发取码，#aa.sm 是最终给后面流程使用的扫码结果。
